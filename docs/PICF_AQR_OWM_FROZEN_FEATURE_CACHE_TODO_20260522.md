2026-05-23 cloud gate correction:

```text
Full dense V-JEPA volume cache: rejected.
Maintained V-JEPA cache: recent temporal suffix only, low-precision on disk.
Measured maintained-cache speedup on the action-aware 2xA100 profile:
  cache-off  step10: 24.65 sec/step
  cache-read step10: 20.48 sec/step
  speedup: about 16.9%
```

Reason: the full 32-slice hierarchical V-JEPA tensor produced about 216 MB per
entry and polluted step time with `/mnt` I/O.  PICF consumes only
`current_map()` and `recent_maps(k)`, so the objective-preserving cache target
is the bounded recent suffix actually consumed by AQR, not the archival full
V-JEPA volume.

Consequence: V-JEPA caching is a correct warm-cache / repeated-sweep
optimization.  It is not the main path to PI0.5-like training speed while
PaliGemma remains trainable and the run uses FSDP full shard, unroll=2,
burnin=1, and the full PICF typed-router/posterior stack.

This TODO is intentionally narrow.  It tracks only deterministic feature caches
for frozen pretrained encoders.  Checkpoint reuse already exists, and teacher
belief artifact reuse is not part of the current plan because it risks turning
previous posterior mistakes into hard training bias.

## Scope

```text
In scope:
  deterministic V-JEPA feature cache
  optional deterministic Sonata feature cache
  optional deterministic AnyTouch feature cache

Out of scope:
  normal model checkpoint reuse
  saved posterior / slot / belief outputs as teacher truth
  cached trainable PaliGemma features
  blind SAM artifacts
```

## Core Principle

A frozen feature cache is valid because the frozen encoder output is a
deterministic function of raw input and fixed preprocessing:

```math
z^v_t = f_{VJEPA}(x^v_{\le t}; \phi_v),
z^p_t = f_{Sonata}(P_t; \phi_p),
z^\tau_t = f_{AnyTouch}(\tau_{\le t}; \phi_\tau),
```

with fixed `phi_v`, `phi_p`, and `phi_tau`.

If those conditions hold, replacing online encoder calls with cached features
does not change the model objective:

```math
L(\theta; f_\phi(x)) = L(\theta; \operatorname{cache}_\phi(x)).
```

This layer directly reduces per-step training cost.  It does not change slot
math, posterior authority, sidecar quality gates, action loss, or PaliGemma
training.

## Cross-Run Reuse

Yes, the same feature cache can be reused across different training runs when
the raw data and frozen encoder contract are identical.

Reusable across:

```text
different random seeds
different learning rates
different action weights
different PICF adapter checkpoints
different PaliGemma checkpoints, if PaliGemma features are not cached
different train/validation schedules
different unroll/burn-in windows, if the cache is keyed by absolute segment
and frame rather than by sampled training step
```

Not reusable across:

```text
changed V-JEPA / Sonata / AnyTouch checkpoint
changed image resize/crop/normalization
changed point-cloud crop, FPS, global_scene_point_cap, camera/depth calibration
changed tactile calibration/background/contact stats/sensor ordering
changed temporal mode or temporal history length
enabled stochastic augmentation without cached augmentation seed
unfreezing the cached backbone
```

Therefore the cache key must be dataset- and config-stable:

```text
dataset id
split
episode / segment id
absolute frame id
view name
backbone name
backbone checkpoint hash
preprocess config hash
temporal mode and history length
calibration hash, when applicable
```

## V-JEPA Cache

V-JEPA is the first target because the current training path calls
`visual_encoder.encode_clip(buffer.get_clip())` every step for configured
static/gripper views.

A correct cache must be generated by causally replaying each segment, not by
encoding isolated frames.  The current runtime consumes:

```text
current_map
recent_maps
view identity
segment reset semantics
```

Minimum stored artifact per `(segment, frame, view)`:

```text
current_map
recent_maps for the configured temporal mode
validity mask / view availability
manifest hash
```

This makes the cache reusable by later runs that sample the same absolute frame
under a different training step or seed.

## Sonata Cache

Sonata cache is second priority.  It is valid only if point construction is
deterministic.

Additional key fields:

```text
camera/depth calibration hash
point sampling/FPS config
crop_radius_m
global_scene_point_cap
point coordinate frame contract
```

Risk:

```text
storage can be large because point tokens are dense.
```

Do not implement this before profiling confirms Sonata is a material fraction
of step time.

## AnyTouch Cache

AnyTouch cache is third priority.  It is mathematically straightforward but
likely a smaller speed win than V-JEPA.

Additional key fields:

```text
tactile sensor names/order
tactile background hash
tactile calibration hash
contact stats hash
tactile clip length/stride
```

## Required Runtime Modes

```text
--frozen-feature-cache-root PATH
--frozen-feature-cache-mode off|read|read_or_encode
```

Semantics:

```text
off:
  always run online frozen encoders.

read:
  require cache hits and fail closed on missing/stale entries.

read_or_encode:
  use cache when valid, otherwise run online encoder.  This is useful for
  progressive cache construction, but production timing comparisons should use
  read mode.
```

## Fail-Closed Contract

The loader must refuse stale artifacts:

```text
hash mismatch        -> hard error
shape mismatch       -> hard error
augmentation enabled -> hard error unless the augmentation seed is cached
missing entry in read mode -> hard error
```

Silent fallback is forbidden for production validation because it can make
speed and loss comparisons meaningless.

## Acceptance Criteria

```text
V-JEPA online-vs-cache feature diff passes tolerance
20-step online-vs-cache training smoke matches within numerical tolerance
A7 step time improves by a measured amount
cache can be reused by at least two different training commands
cache invalidates on checkpoint/preprocess/temporal-config mismatch
```

## Non-Goals

```text
Do not cache trainable PaliGemma features while PaliGemma is trainable.
Do not save posterior/slot outputs as hard teacher labels.
Do not use future-smoothed artifacts as current action evidence.
Do not revive blind SAM through this cache path.
Do not treat cache speedup as behavioral acceptance.
```

## Recommendation

For the current project state:

```text
1. Keep model checkpoint reuse as-is.
2. Remove teacher belief artifact bank from the near-term plan.
3. Build V-JEPA deterministic feature cache first.
4. Profile before adding Sonata or AnyTouch caches.
5. Reuse the cache across future runs only through strict manifest hashes.
```
